# 匯出／匯入（備份）

在「設定 → 匯出／匯入」。程式：`db.exportAll()`、`db.replaceAll()`，畫面在 `app.js` 的 `importBackup`。

## 格式

```json
{ "format": "<APP_ID>-backup", "version": 1, "exported_at": "2026-01-01 08:00:00",
  "tables": { "items": [ { "id": 1, "name": "…" } ], "settings": [ … ] } }
```

- 只匯出 `synced: true` 的表（快取不用備份）。
- `format` 帶 `APP_ID`：別的專案的備份檔放不進來。

## 規則

- **匯入是整個取代**，不是合併。合併會遇到「同一個 id 兩邊內容不同」要選哪個的問題，備份的用途是還原，取代最不會出錯。
- 匯入前先顯示**檔案內容摘要**（匯出時間、每張表幾筆）和**目前的資料量**，打字「取代」才執行。
- 有登入時，取代後全部標成待同步，試算表也會跟著換成檔案的內容。
- 欄位用 `SCHEMA` 整理（缺欄位套預設、多的欄位丟掉），所以舊版本匯出的檔案也能匯入。
- 檔名 `<APP_ID>-backup-YYYY-MM-DD.json`。`.gitignore` 已經擋 `*-backup*.json`：**備份檔是機密，絕不 commit**。

## 什麼時候提醒使用者匯出

- 沒設定 Google 同步（`CLIENT_ID` 空的）：設定頁直接寫「請定期匯出備份」。
- 危險區的「清除」「刪除」：沒登入時說明裡寫「建議先匯出」。
- 匯入前：「不確定的話，先按『匯出』留一份目前的資料。」

## 給 AI／其他程式產生資料

需要大量灌資料（例如把舊 Excel 轉進來）時，產生這個備份格式的 JSON 再用「匯入」最簡單。
color-picker 用過：寫一個本機腳本把真實資料轉成備份格式（腳本和產出都放 `REALDATA/`，gitignore），
再寫一個檢查腳本驗證外鍵、加總、快照一致，才匯入。
